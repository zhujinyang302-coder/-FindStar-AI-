1. 项目背景与目标
1.1 项目背景
校园失物招领信息通常分散在群聊、公告栏或社交平台中。发布者对同一物品的描述可能不同，例如“黑色蓝牙耳机”“无线耳机及充电盒”，导致关键词搜索难以发现潜在关联。系统通过多模态 AI 提取物品特征，并结合文本语义、地点、时间及结构化属性进行候选召回与排序。
1.2 产品目标
让拾获者和失主能够用照片、文字和基本信息快速发布记录。
对失物记录与寻物记录进行自动候选匹配，返回 Top 3 结果及可理解的匹配依据。
建立从发布、匹配、认领申请、审核到完成/关闭的业务闭环。
在华为云环境部署可访问的 Demo，体现 CodeArts 对需求理解、代码生成、问题修复和部署的实际帮助。
保护用户隐私；AI 匹配只用于推荐候选，不自动证明物品归属。
1.3 非目标（首版不做）
不开发原生 Android/iOS App；首版使用响应式 Web。
不实现校园统一身份认证、支付、物流或实时地图导航。
不承诺仅凭图片确认物品所有权。
不在第一版引入复杂微服务、独立向量数据库或自训练视觉模型；先采用模块化单体与可替换的 AI 适配层。
不将真实个人联系方式、证件号、学号、完整序列号等敏感信息公开展示。

3. 核心业务流程
3.1 发布流程
用户选择“我丢了东西”或“我捡到了东西”。
上传 1–5 张物品图片（允许无图发布，但应提示匹配效果可能下降）。
填写标题、描述、类别、颜色、时间、校园地点等字段。
用户可点击“AI 识别特征”；后端调用支持图片输入的模型并返回结构化候选属性。
用户确认或修改属性后提交，后端校验字段、保存数据库记录和图片对象键。
系统返回记录 ID，并提示可以立即进行智能匹配。
3.2 智能匹配流程
用户选择本人有效的寻物或拾获记录，点击“开始智能匹配”。
后端检查记录权限、状态和输入完整性，避免对已关闭记录重复匹配。
按记录类型查询另一侧有效候选记录，过滤已找回、已关闭、违规或不可见记录。
使用结构化字段进行初步筛选；对候选文本计算语义相似度；如支持可靠的图像向量，则计算视觉相似度。
计算综合分数并排序，最多返回 3 条候选；分数、特征和算法版本写入 match_records。
生成解释时只能引用已计算的分项结果和已知事实，不允许模型自行编造匹配分数或私密信息。
前端展示候选、匹配依据、差异点与认领入口；无可靠候选时显示明确的空结果状态。
3.3 认领流程
用户在候选详情页提交认领申请，填写仅供核验的补充特征。
系统将申请状态设为 pending，保存申请人与目标记录关联。
管理员或有权限的物品发布者核验申请；审核时不得把 AI 分数作为唯一依据。
审核通过后，将对应物品状态更新为 claimed/resolved，并关闭冲突申请或使其进入待处理状态。
审核拒绝时记录原因（避免暴露敏感核验答案），申请人可查看状态。
所有状态变更在数据库事务中执行，并写入审计日志。

6. AI 能力与匹配算法规格
6.1 模型调用抽象
后端建立统一 AIProvider 接口，业务逻辑不得直接绑定某一家模型的请求格式。至少提供 extract_item_features(image, description) 和 explain_match(features, score_breakdown) 两类方法。模型供应商、模型名、API 地址和密钥由环境变量配置。若比赛账号可用的模型不支持图片输入，应采用“图像特征模型/人工属性 + 文本大模型”的降级方案。
6.2 结构化特征 Schema
特征提取结果建议包含 category、color、brand、visible_features、description、confidence 和 unknown_fields。category 使用可控枚举；无法识别的字段为 null 或 unknown；所有模型输出均需经过 Pydantic 校验。不得将模型输出直接拼接成 SQL。
6.3 初始匹配公式
初始总分：S = 0.35 × S_text + 0.25 × S_image + 0.20 × S_location + 0.15 × S_time + 0.05 × S_attribute。各分项归一化到 0–1，最终分数显示为 0–100。该权重只是启动实验的基线，需通过标注样本调整。若没有可靠图像向量相似度，则将视觉项替换为结构化视觉特征一致性，并重新归一化权重。
分项
计算建议
注意事项
文本语义 S_text
优先使用可用的文本 embedding 余弦相似度；资源有限时可用模型抽取属性后做规则/语义组合
不能仅比较原始关键词
图片相似度 S_image
使用同一图像编码器生成向量并计算余弦相似度；若未实现则标记为 unavailable
不能把大模型自由生成的分数当作图像相似度
地点 S_location
将校园地点映射为层级/邻近关系，精确地点优先；未知地点返回中性分
不应因地点接近而覆盖明显的类别冲突
时间 S_time
按丢失/拾获时间间隔设置衰减函数，超出业务窗口降低分数
时间未知时不强行判为不匹配
属性 S_attribute
类别、颜色、品牌线索等结构化属性加权一致性
品牌未知不扣分；明确冲突可触发惩罚或过滤
6.4 排序与解释约束
候选集必须来自数据库中另一侧的有效记录，禁止模型凭空生成记录。
候选默认最多 3 条；排序使用后端计算的 score，不使用模型文本中的自报分数。
解释生成只接收已计算的分项、公开字段和差异列表；返回 JSON 并校验。
如果所有候选分数低于配置阈值，显示“暂未找到可靠候选”，不得强行推荐。
保存 algorithm_version、score_breakdown、created_at，便于复现实验和比较不同权重。
6.5 匹配质量评估
建立人工标注的正样本对和负样本对，建议首轮至少准备 50–100 对用于功能验证。
记录 Precision@3、Recall@3、Top-1 命中率、无匹配样本误推荐率。
将样本拆分为调参集与验证集，避免反复根据同一小批样本调权重导致过拟合。
演示页面中将“算法分数”与“真实找回结果”区分显示。

8.1 统一响应格式
成功示例：{"code":0,"message":"success","data":{...},"request_id":"..."}。失败示例：{"code":"VALIDATION_ERROR","message":"请检查输入字段","details":[...],"request_id":"..."}。错误响应不得包含 SQL、堆栈、密钥、内部网络地址或模型供应商的敏感响应头。
8.2 API 约束
使用 Pydantic 校验请求和模型输出；限制分页大小，例如 page_size 最大 50。
创建/审核类接口需考虑幂等性；重复请求不得创建多条相同认领。
涉及两个物品状态同时变化时使用数据库事务和行级锁/乐观锁。
所有用户私有接口从当前登录身份推导 user_id，不信任前端传入的操作者 ID。
匹配接口设置超时、限流和请求 ID；模型调用失败时返回可理解错误。

主要操作在 3 步内可到达；表单提供明确标签、必填提示和错误提示；支持桌面与手机浏览器。
性能
在演示数据规模下，普通列表/详情接口目标 P95 ≤ 1.5 秒（不含模型调用）；AI 接口设置合理超时并提供加载状态。
可靠性
数据库写入失败需回滚；模型失败允许手动填写或重试；缓存失败不影响数据库持久化。
安全
HTTPS；密码哈希；后端鉴权；管理员 RBAC；输入校验；上传文件校验；限流；安全日志。
隐私
公开 API 使用字段白名单；私密核验信息不出现在公开响应和普通日志；支持记录下架/删除流程。
可维护性
前后端分目录；统一配置；类型/Schema 校验；结构化日志；迁移脚本；核心逻辑有单元测试。
可部署性
提供 Dockerfile 和 Docker Compose 作为本地开发选项；云端部署方案以实际获准资源为准。
可观测性
日志包含 request_id、接口、耗时和错误类别；不记录密码、Token、完整私密证据或 API Key。
开源性
提供 LICENSE、README、环境变量示例、部署文档和演示截图；禁止提交 .env、密钥、个人数据。
11. 安全与隐私要求
API Key、数据库密码、Redis 密码和 JWT 密钥必须通过环境变量或获准的密钥管理能力配置，禁止硬编码。
生产环境使用 HTTPS；Cookie 方案需设置 Secure、HttpOnly、SameSite；若使用 Bearer Token，应避免写入 URL 或日志。
图片上传必须限制类型、大小和数量；文件名由服务端生成，禁止直接信任用户文件名。
公开接口只返回白名单字段；发布者身份默认显示昵称或匿名标识，不公开电话、学号、邮箱。
私密核验信息单独存储，限制管理员/授权审核者访问；日志只记录访问事件，不记录完整内容。
模型提示词明确要求把用户输入视为数据而非指令；模型输出经过 Schema 校验，不允许模型直接执行 SQL 或改变权限。
对用户输入做长度限制、HTML 输出转义和适当内容审核；防范 XSS、SQL 注入、提示词注入和恶意上传。
设置数据保留、删除和下架机制；Demo 使用虚构数据，不使用未经授权的真实个人信息。

12.1 MVP 验收门槛
用户能够发布寻物和拾获记录，并在 RDS 中查到记录。
用户能够上传图片并调用真实 AI 服务提取特征；若模型资源不可用，必须明确展示降级状态，不伪装成功。
匹配服务能够返回数据库中真实存在的 Top 3 候选或明确的无结果提示。
匹配分数由后端算法计算；解释与分项结果一致。
认领申请和审核状态能够持久化，越权操作被拒绝。
Redis 至少用于一个真实业务缓存场景，并可通过日志或指标验证命中与失效。
部署后可通过外部浏览器完成核心流程，README 能指导他人复现。

15.1 可直接复制给 CodeArts 的总控提示词
你是本项目的资深全栈工程师。请严格依据《寻物星图 FindStar AI 智能失物招领系统详细软件需求规格说明书》开发，不要擅自删除需求或虚构华为云资源能力。技术基线：- 前端：Vue 3 + Vite + TypeScript + Element Plus。- 后端：Python 3.11+、FastAPI、Pydantic、SQLAlchemy 2.x、Alembic。- 数据库：MySQL（部署时使用获准的华为云 RDS）。- 缓存：Redis（部署时使用获准的华为云 Redis 兼容服务）。- AI：通过后端 AIProvider 适配层接入可用的大模型 API；密钥只从环境变量读取。- 图片：优先使用获准的对象存储；未配置时开发环境可以使用受控本地存储适配器，但生产部署不得依赖临时容器文件系统。开发规则：1. 先阅读需求并输出架构、目录、数据库模型、API 清单和分阶段计划，等待确认后再大规模生成代码。2. 采用模块化单体，不要引入未经需要的微服务或复杂依赖。3. 先实现可运行的业务 MVP，再接入真实 AI 与云服务。4. 所有请求和模型输出都必须校验；所有业务写入必须经过后端权限检查。5. AI 只生成特征或解释；匹配分数由后端算法计算；候选必须来自数据库。6. RDS 是业务数据唯一事实来源；Redis 仅用于缓存/短期状态。7. 不得硬编码密码、API Key、云账号或管理员凭据；提供 .env.example。8. 为核心服务编写单元测试和 API 测试；每次修改后运行相关测试并报告实际结果。9. 不要声称已部署或已连接云服务，除非实际执行并验证成功。10. 每一阶段结束时列出新增/修改文件、运行命令、测试结果、尚未完成项和下一阶段建议。请先只输出实施计划、目录结构、数据库表草案和 API 清单，不要立即生成全部代码。
