## 2. 已实现的自动化测试

位置：`backend/tests/`

- `test_matching.py`：综合评分、类别冲突惩罚、地点/时间中性分、视觉项降级与权重归一化、
  评分可重复性、时间衰减。
- `test_state_machine.py`：合法转换、同状态、非法转换抛 409、终态约束。
- `test_schemas.py`：类别枚举校验、未来时间拒绝、脚本输入防护、图片数量上限。

运行：

```bash
cd backend
pytest
```

## 3. 手工验收清单（MVP）

1. 发布寻物与拾获记录，刷新后数据仍在（数据库持久化）；
2. 无图发布得到“可能降低匹配效果”提示，仍可提交；
3. 对正样本（黑色耳机/教学楼）发起匹配，得到包含类别/颜色/地点一致的候选；
4. 负样本（雨伞 vs 耳机）不因时间地点接近而进入高排名；
5. 匹配分数由后端计算，分项之和与总分口径一致；页面区分“算法分数”与“找回结果”；
6. 认领申请可提交并幂等；重复提交返回既有申请；
7. 普通用户访问 `/admin` 返回 403；未登录访问需鉴权接口返回 401；
8. 上传超大文件返回 413，伪装格式返回 415；
9. Redis 命中与失效可通过日志观察；停用 Redis 后查询仍正常（降级）；
10. `/health/live` 与 `/health/ready` 正常返回。

## 4. 边界与异常覆盖

- 分页超过上限：按上限截断或返回校验错误；
- 非法状态转换：返回 409 并保持原状态；
- 模型超时/非法 JSON：返回降级结果与可读提示，允许手动填写；
- 全部候选低于阈值：返回“暂未找到可靠候选”，不强行推荐；
- 对已关闭记录发起认领或匹配：返回冲突提示。
